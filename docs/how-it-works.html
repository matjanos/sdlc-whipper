The Line

one ticket · one train · one trip

A delivery leaves the yard the moment a ticket is selected and unblocked. It stops at every signal box below — each one a separate agent session with its own model, its own permissions, and a deliberately narrowed view of the world. Between execute and review sits a passing loop: the reviewer sends the work back up to three times, then the line escalates to a human. Click anything.

№ 02

Control interlocks

wired in code · not in prompts

Agents are leaves. Everything below is conductor code — which is why it cannot be talked out of, forgotten, or improvised by a model having a confident day.

INTERLOCK 01

Bounded loops

Executor ⇄ reviewer runs at most 3 laps; stalemate posts both sides to the ticket and parks it. An LLM never decides when to stop.

INTERLOCK 02

Context firewall

The reviewer gets ticket + diff, never the plan. The council gets questions + plan, never the ticket. Golden tests break the build if a prompt leaks.

INTERLOCK 03

Acceptance first

Every task begins with a failing test written before implementation. It is the definition of done for executor, reviewer, CI and tester alike.

INTERLOCK 04

Stateless ticks

All durable state lives in the tracker + git. The conductor reconstructs everything each tick — a crash costs one tick, nothing else.

INTERLOCK 05

Budgets

Per-task ceilings — $15 / 4M tokens by default. Breach → sessions interrupted, ticket parked with a budget-exceeded comment.

INTERLOCK 06

One comment per topic

Escalations — needs-info, stalemate, test-failed… — are edited in place, never reposted. The ticket stays readable.
