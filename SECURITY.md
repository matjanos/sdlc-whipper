# Security policy

## Reporting a vulnerability

Please do not publish exploit details in a public issue.

Use GitHub's **Security → Report a vulnerability** flow when available. Otherwise, open a minimal issue requesting private maintainer contact without including sensitive details.

Include the affected version or commit, impact, reproduction conditions, and any suggested mitigation. Maintainers will acknowledge a report as soon as practical and coordinate disclosure after a fix is available.

## Scope

Security-sensitive areas include command execution, worktree isolation, credential handling, context-firewall boundaries, permission sets, action endpoints, and mutations performed through external-service adapters.
